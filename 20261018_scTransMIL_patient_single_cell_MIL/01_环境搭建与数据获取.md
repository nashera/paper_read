## ① 科学问题与逻辑位置

本模块把"论文里的数据"变成"硬盘上可校验的文件"：

- **上游**：公共门户（KAIST cell atlas、GEO、CELLxGENE、dbGaP、HuggingFace、作者 Google Drive）。
- **下游**：`02` 号做预处理与 bag 构造；`03` 号加载 Geneformer 权重；`06` 号跑基线；`10` 号用 bulk AML 做生存。
- **核心风险**：**版本漂移与 ID 漂移**。泛癌图谱有多个 release；同一个 GEO 号可能被作者更新；Geneformer 词表随版本变化。任何一个错了，后面的 token 化、训练、指标全部不可比。

### 2.2 为什么必须用 Geneformer 的 tokenizer

作者没有自己实现 rank 编码，而是直接调用 Geneformer 的 `TranscriptomeTokenizer`：

- **词表**：`token_dictionary_gc95M.pkl`（Ensembl ID → token ID）。
- **基因中位数**：`gene_median_dictionary_gc95M.pkl`（跨细胞 median scaling，避免高表达基因垄断排序）。
- **rank 规则**：对每个细胞，先按 `n_counts` 做 median scaling，再去掉零表达基因，按数值降序排列，取 token 序列。

自己重写很容易在"median scaling 的参考集""零值过滤时机""token 映射顺序"三处出错，导致序列与作者不一致。**必须复用官方 tokenizer**。

### 4.4 预训练权重

作者 README：

- Geneformer 模型 `gf-6L-30M-i2048`：从 Geneformer 官方发布获取，放到 `raw/pretrained/gf-6L-30M-i2048/`。
- 词表/中位数/Ensembl 映射：`token_dictionary_gc95M.pkl`、`gene_median_dictionary_gc95M.pkl`、`ensembl_mapping_dict_gc95M.pkl`，放到 `raw/pretrained/geneformer/`。
- scTransMIL 预训练权重：作者 Google Drive（`results/bicls_pancancer_s1`、`results/multicls_pancancer_s1`），或 Zenodo 归档。
- scGPT whole-human（仅 FM 变体）。

```bash
# 目录结构应为：
# raw/pretrained/
# ├── gf-6L-30M-i2048/            # config.json, pytorch_model.bin, ...
# ├── geneformer/
# │   ├── token_dictionary_gc95M.pkl
# │   ├── gene_median_dictionary_gc95M.pkl
# │   └── ensembl_mapping_dict_gc95M.pkl
# ├── sctransmil_bicls/           # 可选：作者预训练
# ├── sctransmil_multicls/
# └── scgpt_whole_human/
```

> ⚠️ **必须核对（D10）**：作者代码用 `gf-6L-30M-i2048` 搭配 `gc95M` 字典。但当前 HuggingFace `ctheodoris/Geneformer` 的文件列表只有 `Geneformer-V1-10M`、`V2-104M`、`V2-316M`，**没有 `gf-6L-30M-i2048` 目录，也没有 `*_gc95M.pkl` 字典**（现有 `*_gc30M.pkl`/`*_gc104M.pkl`）。可选路径：① 从 Geneformer V1 的历史 release/Zenodo 或作者 Google Drive 找 checkpoint + `gc95M` 字典；② 用 `Geneformer-V1-10M`（config：6 层、hidden 256、4 heads、max_position 2048，~10M 参数）搭配 `gc30M` 字典替代，并在方法学声明。二者 hidden size 都是 256，与作者 `CLAM_SB` 的 `L=256` 兼容。

### 4.5 泛癌图谱

```bash
# code/01_02_fetch_pancancer.sh
# 1) 从 https://cellatlas.kaist.ac.kr/ecosystem/ 下载 104 个 h5ad（清单见作者 README）
# 2) 统一命名：<cancer>_<GSE/EGA>.h5ad
# 3) 校验：每个文件必须含 obs 列 Patient / Tissue / cnv_status / Cancer type
```

```python
# code/01_03_check_pancancer.py
import glob, anndata as ad, pandas as pd
rows = []
for f in sorted(glob.glob("raw/pancancer/*.h5ad")):
    a = ad.read_h5ad(f, backed="r")
    rows.append(dict(file=f.split("/")[-1], n_cells=a.n_obs, n_genes=a.n_vars,
                     has_patient="Patient" in a.obs,
                     has_tissue="Tissue" in a.obs,
                     has_cnv="cnv_status" in a.obs,
                     has_cancer="Cancer type" in a.obs))
df = pd.DataFrame(rows)
df.to_csv("results/01_pancancer_inventory.csv", index=False)
print(df.describe())
print("total cells:", df.n_cells.sum(), "files:", len(df))
```

**预期**：104 个文件，`total cells ≈ 4,000,000`；四列齐全。缺列的文件必须回到门户确认版本。

## ⑦ 常见陷阱与排错表

| 现象 | 根因 | 解决 |
|---|---|---|
| `Geneformer` 安装失败 | 缺 `git lfs` / 版本冲突 | `git lfs install`；用官方 requirements |
| `smooth-topk` 编译失败 | 无 CUDA / 编译器不匹配 | 用 CUDA 版本；或临时 CE（声明） |
| h5ad 读入报 `X` 非稀疏 | 门户版本差异 | `scipy.sparse` 转换；记录 |
| `cnv_status` 缺失 | 下载了未注释版本 | 回门户核对 release |
| token 字典找不到基因 | Ensembl 版本不同 | 用作者 `gene_id.csv` 映射；记录丢失率 |
| 下载中断 | 大文件 | `wget -c` 断点续传；md5 校验 |
| dbGaP 无权限 | 未申请 | 走 eRA；未获批则标记未复现 |
| 显存 OOM | 序列 1024 × 256 cells | 降 `max_len` 或 bag 大小（声明） |

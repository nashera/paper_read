> **目标文献**：Hoffman GE, et al. *Efficient differential expression analysis of large-scale single-cell transcriptomics data using Dreamlet.* Nature Communications (2026) 17:9597. DOI: 10.1038/s41467-026-75680-8

## ① 科学问题与逻辑位置

- **上游**：同一份 pseudobulk（AD）与同一份细胞级数据。
- **下游**：`results/13_*.csv`、`figures/FigS9–S18.*`；14 号的批判性评述。
- **本模块回答三个"审稿人一定会问"的问题**：
  1. **换一个 DE 方法，结论会变吗？**（dreamlet vs limma vs DESeq2）
  2. **换一个队列，结论会变吗？**（与 Mathys 2023 的跨队列一致性）
  3. **把 batch 当随机效应，和"先 Harmony 再当协变量"，哪个更稳？**

> ⚠️ **导师批注**：这一模块不是"证明 dreamlet 最好"，而是**量化"方法选择带来的不确定性"**。如果三个方法的 logFC 相关只有 0.7，那么任何"某基因显著"的结论都必须附带"方法敏感性"说明。

---

## ② 背景原理

### 2.1 三种 DE 方法的本质差异

| 维度 | dreamlet | limma-voom | DESeq2 |
|---|---|---|---|
| 数据 | pseudobulk log2 CPM | pseudobulk log2 CPM | pseudobulk 原始计数 |
| 模型 | **线性混合模型**（固定 + 随机） | 线性模型（仅固定） | 负二项 GLM（仅固定） |
| 方差 | 观测权重 + EB 收缩 | 观测权重 + EB 收缩 | 离散度收缩（NB） |
| 随机效应 | ✅ | ❌ | ❌ |
| 零分布 | moderated t（LMM 近似 df） | moderated t | Wald / LRT（渐近） |
| 对批次 | `(1|poolID)` | 只能 `+ poolID`（固定） | 只能 `+ poolID`（固定） |

**预期**：

- 在**没有强批次**的细胞类型里，三者 logFC 高度相关（ρ>0.9）。
- 在**强批次**的细胞类型里（如 NXPE1 所在），limma/DESeq2 若把 pool 当固定效应，会因 df 消耗而**低估显著性**；若不放 pool，则**FPR 膨胀**。
- DESeq2 的 logFC 会因 NB 收缩而与 log2 CPM 方法有系统差异（尤其低表达基因）。

### 2.2 跨队列一致性

Mathys et al. 2023（Cell）是另一套 AD snRNA-seq。原文把两套数据的 DE 结果（logFC）做相关，发现：

- dreamlet 的跨队列 logFC 相关**最高**；
- PTPRG 在两项研究中都是 microglia 的 top finding。

跨队列一致性受多种因素影响：队列构成、测序平台、注释体系、疾病阶段。**相关高 ≠ 结果可互换**；它只说明"信号方向稳定"。

### 2.3 Harmony vs 随机效应

**Harmony**：在 PCA 空间里迭代校正 batch，输出一个"去批次"的嵌入。常见 downstream 用法是把前 $k$ 个 Harmony 成分作为协变量放进回归。

**随机效应**：直接在表达尺度上建模 batch 的方差。

原文的论点：

- 10X pool 解释了**Harmony 成分之外**的显著方差（Fig. S14–S15）——说明 Harmony 没有完全去掉 pool 效应；
- 在 pool vs Harmony 两种建模下，DE 统计量变化最大的基因，正是那些 **pool 方差分数高**的基因（Fig. S16–S18）。

> ⚠️ **导师批注**：Harmony 是为**聚类/可视化**设计的，不是为"去除表达尺度上的批次效应"设计的。把它当前处理放进 DE，等于假设"前 5 个成分捕获了全部批次"——原文用数据否定了这个假设。复现时要把这句话写进方法学。

## ④ 逐步可运行代码

### 4.1 同一份 pseudobulk，三种方法

```r
# code/13_01_three_methods.R
suppressPackageStartupMessages({
  library(SingleCellExperiment); library(limma); library(DESeq2)
  library(dreamlet); library(BiocParallel); library(dplyr)
})

pb_obj <- readRDS("processed/pb_psychad.rds")
pb <- pb_obj$pb
cd <- as.data.frame(colData(pb))
cd$Dx <- factor(cd$Dx, levels = c("Control","AD"))

run_limma <- function(k) {
  y <- assay(pb, k)
  dge <- edgeR::DGEList(y); dge <- edgeR::calcNormFactors(dge, method = "TMM")
  design <- model.matrix(~ Dx + scale(Age) + Sex + poolID, data = cd)
  v <- limma::voom(dge, design, plot = FALSE)
  fit <- limma::lmFit(v, design)
  limma::eBayes(fit)
}

run_deseq2 <- function(k) {
  dds <- DESeq2::DESeqDataSetFromMatrix(assay(pb, k), cd, ~ Dx + Age + Sex)
  dds <- DESeq2::DESeq(dds, quiet = TRUE)
  DESeq2::results(dds, contrast = c("Dx","AD","Control"))
}

run_dreamlet <- function(k) {
  topTable(readRDS("processed/fit_psychad.rds")[[k]], coef = "DxAD", number = Inf, sort.by = "none")
}

ct <- "Micro_PVM"
res <- list(
  dreamlet = run_dreamlet(ct),
  limma    = run_limma(ct),
  deseq2   = run_deseq2(ct)
)
saveRDS(res, "processed/13_three_methods_Micro_PVM.rds")
```

> DESeq2 的 `~ Dx + Age + Sex` 没有放 `poolID`（60 个水平会让设计矩阵巨大且共线）；limma 放了 `poolID` 固定效应。**这不是公平对照**——但正是原文想说明的：能建模随机效应的方法（dreamlet）才能既控批次又不耗 df。对照结果要按这个前提解释。

### 4.2 方法间 logFC 相关与差异

```r
# code/13_02_compare_methods.R
suppressPackageStartupMessages({ library(dplyr); library(ggplot2); library(ggpointdensity) })

res <- readRDS("processed/13_three_methods_Micro_PVM.rds")
df <- data.frame(
  gene = rownames(res$dreamlet),
  dreamlet = res$dreamlet$logFC,
  limma    = res$limma$coefficients[, "DxAD"],
  deseq2   = res$deseq2$log2FoldChange
)
df <- df[complete.cases(df), ]

cors <- data.frame(
  pair = c("dreamlet_limma","dreamlet_deseq2","limma_deseq2"),
  pearson  = c(cor(df$dreamlet, df$limma), cor(df$dreamlet, df$deseq2), cor(df$limma, df$deseq2)),
  spearman = c(cor(df$dreamlet, df$limma, method="spearman"),
               cor(df$dreamlet, df$deseq2, method="spearman"),
               cor(df$limma, df$deseq2, method="spearman"))
)
print(cors)
write.csv(cors, "results/13_method_logfc_correlation.csv", row.names = FALSE)

p <- ggplot(df, aes(dreamlet, limma)) +
  geom_pointdensity(size = 0.3) + geom_abline(slope = 1, intercept = 0, color = "red") +
  theme_classic() + coord_equal()
ggsave("figures/FigS11_dreamlet_vs_limma.png", p, width = 5, height = 5, dpi = 300)
```

**判据**：Spearman ρ > 0.9（dreamlet vs limma）、> 0.85（dreamlet vs DESeq2）。低于此值先查基因匹配与归一化。

### 4.4 Harmony vs 随机效应

```r
# code/13_04_harmony.R
suppressPackageStartupMessages({
  library(harmony); library(SingleCellExperiment); library(scater); library(scran)
})

sce <- readRDS("processed/sce_psychad_annot.rds")

# 1) 标准 Harmony（按 pool）
sce <- runPCA(sce, ncomponents = 30)
sce <- RunHarmony(sce, group.by.vars = "poolID", reduction = "PCA",
                  reduction.save = "HARMONY", seed = 20261018)

# 2) 取前 5 个成分，写回 pseudobulk 的样本级协变量
harm <- reducedDim(sce, "HARMONY")[, 1:5, drop = FALSE]
# ★ 统一列名为 V1..V5（实际可能是 harmony_1..5），避免后面取到 NULL
harm_df <- as.data.frame(harm)
colnames(harm_df) <- paste0("V", seq_len(ncol(harm_df)))
harm_df$Channel <- sce$Channel
harm_mean <- aggregate(. ~ Channel, data = harm_df, FUN = mean)
rownames(harm_mean) <- harm_mean$Channel
stopifnot(all(paste0("V", 1:5) %in% colnames(harm_mean)))

pb_obj <- readRDS("processed/pb_psychad.rds")
pb <- pb_obj$pb
cd <- as.data.frame(colData(pb))
cd <- cbind(cd, harm_mean[rownames(cd), paste0("V", 1:5)])
```

> 上面已把列名统一成 `V1..V5`；若改用其他成分数，记得同步改 `form_harmony`。把 5 个成分加入 `processAssays`/`dreamlet` 的公式：

```r
form_harmony <- ~ V1 + V2 + V3 + V4 + V5 + (1|SubID) + scale(Age) + Dx
fit_h <- dreamlet(processAssays(pb, form_harmony, min.cells = 5, min.count = 10,
                                BPPARAM = SnowParam(12)),
                  form_harmony, BPPARAM = SnowParam(12))
saveRDS(fit_h, "processed/fit_psychad_harmony.rds")
```

### 4.5 方差解释对照 + 变化最大的基因

```r
# code/13_05_harmony_vs_pool.R
vp <- as.data.frame(readRDS("processed/vp_psychad.rds"))

# (a) pool 方差分数 vs 是否被 Harmony 成分解释
# 简化：把 pool 方差分数按细胞类型汇总，与 Harmony 模型的 DE 变化做相关
tt_pool <- read.delim("results/topTable_psychad_DxAD.tsv")
tt_h    <- as.data.frame(topTable(readRDS("processed/fit_psychad_harmony.rds")[["Micro_PVM"]],
                                  coef = "DxAD", number = Inf, sort.by = "none"))
tt_h$ID <- rownames(tt_h)

df <- tt_pool[tt_pool$assay == "Micro_PVM", c("ID","t")] |>
  inner_join(tt_h[, c("ID","t")], by = "ID", suffix = c("_pool","_harmony")) |>
  inner_join(vp[vp$assay == "Micro_PVM", c("gene","poolID")], by = c("ID" = "gene"))

df$delta_t <- abs(df$t_pool - df$t_harmony)
cat("Spearman(delta_t, pool variance):",
    cor(df$delta_t, df$poolID, method = "spearman"), "\n")

p <- ggplot(df, aes(poolID, delta_t)) + geom_point(size = 0.4) +
  geom_smooth(method = "lm") + theme_classic() +
  labs(x = "Variance explained by 10X pool", y = "|Δt| between models")
ggsave("figures/FigS16_delta_t_vs_pool.png", p, width = 5, height = 4, dpi = 300)
```

**预期**：正相关（ρ>0），即"批次方差越大的基因，两种建模下统计量变化越大"。

## ⑤ 参数解释与调参空间

| 参数 | 本项目取值 | 可选 | 改变后果 |
|---|---|---|---|
| limma 设计 | `Dx + Age + Sex + poolID`（固定） | 不放 pool | 不放 → FPR 膨胀；放 → df 消耗 |
| DESeq2 设计 | `Dx + Age + Sex` | 加 pool | 数十个 pool 会让设计矩阵不稳 |
| Harmony 成分数 | 5（原文） | 10/20 | 成分越多越接近"去干净"，但会吸收生物信号 |
| Harmony 的 `group.by.vars` | `poolID` | 加 `SubID` | 去供体效应会伤及生物学 |
| 跨队列基因匹配 | inner join | outer | 只保留共同基因 |
| 相关方法 | Spearman（主）+ Pearson | — | 离群基因影响 Pearson |

## ⑦ 常见陷阱与排错表

| 现象 | 根因 | 解决 |
|---|---|---|
| limma 的 logFC 与 dreamlet 差很多 | limma 未加权 / 未放 pool | 用 `voom` + 权重；对照设计 |
| DESeq2 结果全是 NA | 设计矩阵共线 / 低表达 | 去掉 pool；`independentFiltering` |
| Harmony 后 DEG 反而更多 | 成分吸收了生物信号 | 减少成分数；只按 pool 校正 |
| 跨队列匹配率低 | 基因 ID 版本不同 | 统一 Ensembl/SYMBOL；记录交集 |
| 相关很高但斜率≠1 | 归一化/收缩差异 | 报告斜率与 Bland–Altman |
| Mathys 数据不可得 | 受控访问 | 登记 gap；不伪造 |
